## REQUIREMENTS
1. Use Docker Compose v2 syntax.
2. Use a Node.js 24 slim Debian-family development image.
3. Run containers as non-root.
4. Do not use privileged mode or mount docker.sock.
5. web publishes host port 3000 and binds 0.0.0.0 in-container.
6. worker runs continuously with source-watch/restart behavior.
7. Source edits to web/shared packages are reflected without full image rebuild.
8. Source edits to worker/shared packages restart or reload the worker without full image rebuild.
9. Host node_modules is neither required nor bind-mounted.
10. No real credential is needed for startup.
11. Add stable root scripts: docker:up, docker:down, docker:rebuild, docker:ps, docker:logs.
12. Windows Docker Desktop file watching must work; use documented polling environment flags only if necessary.
13. Existing npm run validate must continue passing.
14. Any added direct dependency is exact-pinned and justified in evidence.
15. Docker services have stable names and useful health/status output.
16. Leave services running after successful validation.

## ARCHITECTURE RULES
Development Docker is not production deployment. Do not move PH-M11 responsibilities earlier. Reuse the existing npm-workspaces foundation. Avoid duplicate dependency installation logic across services by sharing one dev image.

## CONSTRAINTS
Inspect repository and Docker availability first. If Docker Engine/Compose is unavailable, STOP as BLOCKED with exact evidence rather than faking runtime validation. No force-push/history rewrite. Do not expand into PH-M01.
