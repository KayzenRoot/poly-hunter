## OBJECTIVE
Implement the first PH-M01 increment: local Postgres persistence, code-owned migrations and a tenant-scoped repository boundary, without introducing external authentication or secret storage.

## CONTEXT
PH-M00 is complete and local Docker is canonical. PH-M01 plan freezes PostgreSQL + Drizzle and a server-derived TenantContext. This increment lays the persistence/isolation foundation that later identity and secret work will use.

## REQUIREMENTS
1. Local Postgres uses a pinned PostgreSQL 17 image reference and persistent named volume.
2. No database port is exposed beyond localhost unless technically required by the host test workflow; prefer container-only networking.
3. Runtime DB URL is server-only.
4. All direct dependencies are exact-pinned; lockfile committed.
5. Migrations are code-owned/versioned and deterministic.
6. IDs are UUIDs; timestamps are UTC.
7. tenant slug unique; identity link unique(provider,subject); membership unique(tenant_id,user_id).
8. Role values limited to owner/admin/member; platform_admin is NOT a tenant role.
9. A TenantContext cannot be constructed from arbitrary client JSON; creation lives in server/application boundary.
10. Tenant-scoped repositories require TenantContext and include tenant_id in every tenant-owned query predicate.
11. No generic unscoped repository for tenant-owned records is exported to web/application consumers.
12. Integration tests create at least two tenants and prove cross-tenant reads/writes cannot escape the supplied TenantContext.
13. Foreign keys, unique constraints and delete behavior are explicit and tested.
14. Migrations can apply from empty DB repeatedly in disposable test databases.
15. CI runs integration tests against PostgreSQL.
16. Local Docker web remains healthy on localhost:3000 and worker remains running after database addition.
17. No real credential or auth provider is required.
18. No HIGH/CRITICAL dependency/security finding is accepted.
19. Produce migration recovery/roll-forward notes in Evidence Bundle.
20. Leave local Docker stack running at STOP CONDITION.

## ARCHITECTURE RULES
- `packages/domain` does not import DB/Drizzle.
- `packages/db` may depend on contracts/domain types only in the allowed dependency direction.
- No Supabase Data API coupling.
- No browser import of server DB modules.
- Keep connection lifecycle explicit; tests must close pools/clients deterministically.
- No SQL string interpolation with untrusted values.
