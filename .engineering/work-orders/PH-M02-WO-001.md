## OBJECTIVE

Introduce PolyHunter's public/read-only Polymarket provider boundary.

This Work Order establishes provider-neutral contracts plus the official-provider adapter for:
- market discovery/metadata;
- current public order-book/price data;
- public market real-time updates;
- reconnect/stale/error state.

It MUST NOT add any credential-bearing or money-moving capability.

## PREFLIGHT: OFFICIAL PROVIDER REVALIDATION

Before choosing dependencies or wire contracts, revalidate the current official Polymarket docs.

At minimum confirm:
- current TypeScript SDK/package name and version range;
- public market discovery surface;
- public book/price surface;
- market WebSocket endpoint/topic/events;
- connection/heartbeat/reconnect requirements exposed by SDK/wire docs;
- current error/rate-limit guidance relevant to public reads.

Prefer the official unified SDK when it exposes the needed stable capability.

If an official SDK lacks a required read-only surface, a direct HTTP/WebSocket implementation is allowed only inside `packages/polymarket`, with exact evidence explaining why.

Lock exact dependency versions in package-lock.

## REQUIRED PACKAGE BOUNDARY

Create:
`packages/polymarket`

Only this package may import the Polymarket SDK.

Provider-neutral types/ports must live in PolyHunter-owned packages.

Minimum provider-neutral concepts:
- MarketId / ConditionId / AssetId opaque identifiers;
- market summary/detail;
- outcome/asset mapping;
- decimal-string price/size representation without JS floating-point authority;
- order-book snapshot;
- book level;
- market stream event union;
- provider connection health/staleness state;
- normalized provider error code/category.

Do not leak official SDK classes/types through exported provider-neutral interfaces.

## PUBLIC DISCOVERY

Implement a read-only boundary capable of:
- listing/discovering active markets with bounded pagination;
- fetching market detail by supported provider identity;
- exposing condition/outcome/asset identifiers required by downstream book subscriptions;
- normalizing active/closed/resolved state;
- rejecting malformed provider payloads fail-closed.

Do not implement PH-M03 ranking/filter strategy here.

## PUBLIC BOOK/PRICE

Implement read-only access for the minimum public data needed by PH-M03:
- current order book;
- best bid/ask when available;
- tick size;
- minimum order size when available;
- last trade price when available;
- current fee metadata needed to interpret the market when publicly exposed.

Use decimal strings or an exact decimal abstraction. Do not use binary floating point as canonical provider price/size state.

## PUBLIC MARKET STREAM

Implement the official public market stream adapter.

Normalize the currently documented event families required for market state:
- book snapshot/update;
- price change;
- last trade price;
- tick-size change;
- optional top-of-book/lifecycle events when officially supported and useful.

The adapter must expose deterministic connection state:
- CONNECTING;
- SYNCING if needed;
- LIVE;
- STALE;
- DISCONNECTED.

Staleness threshold must be explicit/injected, not hidden in business logic.

On unknown/malformed stream state:
- surface provider error/stale state;
- do not fabricate book correctness.

## RECONNECT / BACKOFF

Implement bounded reconnect/backoff behavior.

Requirements:
- no unbounded retry storm;
- deterministic testability via injected clock/backoff/randomness or equivalent test hook;
- reconnect does not silently preserve stale book state as LIVE;
- downstream consumer can distinguish reconnected/fresh from stale/unknown state;
- subscription resync/snapshot semantics are tested.

No trading decision exists in this Work Order.
