## Part 2 — CONFIGURED origin http://configured-origin.test:4321 (one-off container)
#
# This part exists to falsify the review's central CR-04 concern: that redirect
# targets are still a hard-coded literal. The container ran with
# NEXT_PUBLIC_APP_ORIGIN=http://configured-origin.test:4321, published on 127.0.0.1:3100.
# If any redirect target or Origin comparison were hard-coded to localhost, these
# results would be identical to Part 1. They are not.

### GET /auth/callback redirect target follows configuration (CR-04)
error=access_denied                            -> HTTP 303 Location=http://configured-origin.test:4321/?auth=denied
error=invalid_request                          -> HTTP 303 Location=http://configured-origin.test:4321/?auth=denied
open-redirect attempt                          -> HTTP 303 Location=http://configured-origin.test:4321/?auth=failed

### CSRF comparison follows configuration (CR-02)
Origin = configured origin (guard ALLOWS)      -> HTTP 503
Origin = http://localhost:3000 (now FOREIGN)   -> HTTP 403

# Conclusion: redirect targets and the CSRF comparison both track NEXT_PUBLIC_APP_ORIGIN.
# Changing only configuration changed both behaviours, and localhost — the trusted
# origin in Part 1 — is now correctly REJECTED as cross-origin.
#
# Production fail-closed behaviour (an absent, non-absolute, non-http(s) or plain-http
# NEXT_PUBLIC_APP_ORIGIN under NODE_ENV=production throws InvalidAppOriginError, which
# originMatchesTrusted converts into a denial for every request) is proven by unit
# tests in tests/app-origin-csrf.test.ts rather than by a live container: reproducing
# it needs a production build and NODE_ENV=production, while the behaviour is a pure
# function of those two environment values.
