## The defect
GitHub Actions Validate run 37487821234 failed with ERR_MODULE_NOT_FOUND for
`@polyhunter/db/server/vault`. The workspace `exports` map pointed every
condition at `./dist/server/vault/index.js`, a build output that does not exist
in a clean checkout. `npm test` ran before any workspace build, so the module was
simply absent — and on a developer machine a STALE `packages/**/dist` from an
earlier build would have hidden the defect entirely.

## Strategy chosen (ONE coherent strategy: source-first workspace exports)
Every `exports` condition of every workspace now points at `./src/**/*.ts`. No runtime
consumer needs a `dist` directory at all, so no step can depend on one.
The supporting changes, and why each was necessary rather than cosmetic:
  - relative `.js` specifiers inside packages rewritten to `.ts`;
  - `allowImportingTsExtensions` + `rewriteRelativeImportExtensions` on the emitting
    workspaces, so the emitted JavaScript still points at `.js`;
  - `transpilePackages` in apps/web/next.config.ts, which applies to the Next dev
    server AND the production build;
  - SIX vitest aliases removed, including the two (@db/vault/envelope,
    @db/vault/keyring) that would have masked the defect, replaced by real subpath
    exports so resolution goes through the genuine `exports` map.
tests/workspace-boundaries.test.ts now FAILS THE BUILD if any workspace export
condition ever points back at `dist/`.
