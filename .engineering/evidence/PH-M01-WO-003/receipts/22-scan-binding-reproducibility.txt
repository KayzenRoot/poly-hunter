PH-M01-WO-003 — scan/artifact binding + reproducibility (CR-05..CR-08 round)
generated: 2026-10-06T17:58Z

THE QUESTION. Every VEX re-measurement in this bundle answers questions about the
artifact the scan analysed. If the committed scan (14-image-scan.sarif) belonged to a
different image — the previous digest, or whatever the `polyhunter-dev:local` tag
happened to point at — every disposition would be about the wrong artifact and nothing
else in the bundle would notice.

WHY THE SARIF CANNOT CARRY THE ANSWER. docker scout 1.24.0's SARIF has NO
run.properties, no invocations, no artifacts, no image name and no digest anywhere in
the document. Measured on the committed scan, not assumed: `run.properties` is
`undefined`, and a byte-level search finds neither the current digest nor any prior one
(the words "polyhunter" and "digest" do not occur either). A binding check that reads
the SARIF alone therefore passes VACUOUSLY — the first revision of the check in
vex-state-machine.mjs did exactly that. It was found by measurement, made to read the
scout stderr receipt instead, and the fixed check was then observed to FAIL (control A
below). The SARIF-properties branch is kept so the gate tightens automatically if a
future scout starts emitting identity metadata; scout 1.24.0 is never relied upon to
satisfy it.

== 4. the same rule enforced inside the generator ==

vex-state-machine.mjs REFUSES to write any receipt unless the scan's stderr receipt
(14-image-scan.stderr.txt) names the declared digest. The original scan's stderr names
it in the temporary-archive cleanup warning — which is INCIDENTAL: that warning exists
only because the temp file was still in use. The digest-pinned re-run's stderr does not
name it (its cleanup succeeded). That fragility is exactly why (a) the check reads a
required receipt and fails closed rather than passing when it cannot see the digest,
and (b) the digest-pinned re-scan in §1 exists as separate, structural evidence rather
than resting on the warning.

== 5. why the SARIF is byte-identical ACROSS rounds ==

The CR-01..CR-04 scan (of `8bd3e85a…`) and the CR-05..CR-08 scan (of `aee3ad8c…`) are
ALSO byte-identical to each other — git records the pair as a 100% rename. Stated
plainly, that is the expected result and not a copy: scout's SARIF carries no image
identity and no timestamp; the scanned package/version set is objectively equivalent
(88-package dpkg inventory diff = 0; every npm purl version equal across rows); and the
scanner datasource state was unchanged between two runs taken on the same day. The byte
identity is evidence of CONTENT equivalence, and it is deliberately not used as the
binding — the binding is §2's digest-pinned run, whose target was the digest itself.

== 6. regeneration is deterministic ==

Re-running `vex-state-machine.mjs` on unchanged inputs reproduces
`14-vex-state-machine.json` byte-for-byte apart from nothing at all (the JSON carries no
`generated` timestamp field), and the markdown companion is likewise unchanged by
re-runs. The receipt pair committed in this round was produced by a clean run AFTER the
last mutation of both controls, with the original stderr receipt restored (`2/2` digest
occurrences re-verified present before the run).
